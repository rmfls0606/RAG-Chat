## 현재까지 진행 사항

#### 지난 회차 액션 아이템

- 1회차 멘토링이라 해당 없음

#### 프로젝트 구조 (처음 보시는 분을 위한 요약)

- **데이터**: MS MARCO QnA(실제 Bing 검색 질문 + 질문마다 검색된 문단 10개 + 사람이 쓴 정답)
- **의료 질문 선별**: 의료 사이트 33개 목록을 만들고, 질문의 문단 10개 중 2개 이상이 이 사이트에서 왔으면 건강 질문으로 분류
- **파이프라인**: 질문 → bge-base-en-v1.5 임베딩 검색(FAISS) 상위 100개 → MiniLM 크로스인코더 재정렬 → 상위 5개 → Qwen2.5-7B-Instruct가 문서 [1]~[5] 안의 내용으로만 답변하고 문장마다 [번호] 출처 표시
- **안전장치**: 근거가 약하면(재정렬 최고 점수가 기준 미만) 답하지 않음, 출처 사이트 등급(공공기관·병원·상업 매체·커뮤니티) 표시

#### 진행 내용

- 완료 사항
    - **데이터 구축 (v1.1 기준)**: 문단 DB 142,605개, 평가셋 550문항(건강 500 + 분야 밖 50), 모델 선택용 검증셋 200문항(평가셋과 겹치지 않음)
        - v2.1로도 같은 과정을 진행함: 문단 459,067개, 평가셋 650문항(답 있음 500 + 답 없음 100 + 분야 밖 50)
    - **검색 베이스라인** (v1.1, 건강 500문항)

        | 방법 | R@1 | R@5 | R@10 | R@100 | MRR@10 |
        | --- | --- | --- | --- | --- | --- |
        | BM25 | 0.118 | 0.340 | 0.466 | 0.798 | 0.213 |
        | bge-base (dense) | 0.236 | 0.596 | 0.754 | 0.976 | 0.385 |

    - **검색 개선 실험** (v1.1, 같은 500문항)
        - Hybrid(BM25 + dense, RRF): R@10 0.650으로 dense 단독(0.754)보다 낮음
        - 재정렬: dense → MiniLM-L-6 MRR 0.449 / R@10 0.784, dense → bge-reranker-base MRR 0.422 / R@10 0.790
        - 리랭커 5종 비교(팀원 진행): MiniLM-L-6이 MRR 0.450으로 가장 높음, dense 대비 향상 폭 95% 신뢰구간 +0.040 ~ +0.094
        - 참고 상한: 질문 대신 정답 문장으로 검색하면 R@10 0.846 → 질문 표현과 문단 표현의 차이가 검색 오류의 큰 원인으로 보임
    - **RAG 챗봇 구현**: 위 파이프라인 + 중복 문단 제거 + 출처 등급 + 거절 기준(검증셋 재정렬 최고 점수의 하위 5%)
        - Gradio 챗봇 화면(왼쪽 대화, 오른쪽 근거 문단과 출처 등급)을 Colab A100에서 띄워 동작 확인
    - **생성 평가** (건강 100문항 + 분야 밖 50문항): LLM 단독(B0) vs RAG 기본 vs RAG 개선

        | 방법 | F1 | ROUGE-L | 출처 표시 비율 | 잘못 거절 (건강) | 분야 밖 거절 비율 | 응답 시간 (초/질문) |
        | --- | --- | --- | --- | --- | --- | --- |
        | LLM 단독 (B0) | 0.207 | 0.168 | - | 0.00 | 0.28 | 0.13 |
        | RAG 기본 | 0.268 | 0.237 | 0.99 | 0.01 | 0.48 | 0.33 |
        | RAG 개선 (중복 제거 + 거절 기준) | 0.253 | 0.227 | 1.00 | 0.08 | 0.86 | 0.26 |

        - RAG가 LLM 단독보다 F1 +0.06, ROUGE-L +0.07, 답변의 99% 이상에 출처 표시
        - 거절 기준을 넣자 분야 밖 거절률이 0.48 → 0.86으로 올랐지만, 답할 수 있는 건강 질문도 8% 거절해 F1이 조금 내려감
        - 정답 문단이 상위 5개 안에 있는 비율(근거 R@5)은 0.61

- 진행 중인 사항
    - 생성 모델 LoRA 파인튜닝: RAG 형식(질문 + 검색 문단 5개 → 정답 [번호]) 학습 실행 중 (출처 불분명 문단 감점 함께 비교)
    - 생성 평가 결과 정리, 틀린 답변 사례 분석
    - 발표용 데모 질문 선정(잘 답하는 질문 3, 거절하는 질문 1, 출처가 돋보이는 질문 1)
- 하지 못한 사항 / 보류 중인 사항
    - LLM-as-a-judge로 근거 충실도 평가
    - v1.1용 "답 없는 질문" 만들기: v1.1에는 답 없는 질문이 없어서, 정답 문단을 빼는 방식으로 100개 만들 예정
    - 의료 질문 판정 개선: 사이트 목록 대신 LLM 판정 + 사람 확인

#### 지난 회차 대비 달라진 점

1회차라 처음 계획과 비교해 바뀐 점을 정리했습니다.

- **데이터 버전**: v2.1로 먼저 실험한 뒤, 재정렬 실험과 챗봇은 v1.1 기준으로 진행했습니다. v1.1에는 답 없는 질문이 없어서 거절 평가는 분야 밖 질문 50개로 대신했습니다.
- **Hybrid 검색 제외**: BM25를 섞으면 dense 단독보다 성능이 떨어져 최종 파이프라인에서 뺐습니다.
- **재정렬 모델 선택**: 검증셋에서는 bge-reranker가 더 좋았지만(MRR 0.521 vs 0.498) 평가셋에서는 MiniLM이 더 좋았습니다(0.449 vs 0.422). 리랭커 5종 비교 결과와 속도(FP16에서 질문당 1초 안쪽)를 함께 보고 MiniLM을 쓰기로 했습니다.
- **거절 기준 추가**: 프롬프트로 "답할 수 없다"고 말하게 하는 것 외에, 재정렬 점수가 낮으면 LLM을 부르지 않고 바로 거절하도록 바꿨습니다.
