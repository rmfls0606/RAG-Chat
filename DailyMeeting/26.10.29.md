# 프로젝트 목표: 의료 도메인 RAG 챗봇

#### 1차 목표: 신뢰할 수 있는 의료 RAG 파이프라인 구축 (MS MARCO v1.1)

- **목표:** 의료 문서에서 근거를 찾아 답하되, **근거가 없으면 답하지 않고, 답할 때는 완전한 문장으로 답한다.**
- **주요 작업**
    - 전처리: URL 화이트리스트로 의료 passage를 추려 코퍼스를 만들고(약 6~7만 개, 추정), 의료 질문과 정답 passage를 연결한 평가 세트를 만든다.
    - 인덱싱: BM25 인덱스와 벡터 인덱스(FAISS)를 만든다.
    - 검색 → rerank → LLM 생성 파이프라인을 구현한다.
    - **답변 불가 판단:** rerank 최고 점수가 임계값보다 낮으면 LLM을 호출하지 않고 "답할 수 없음"으로 응답한다. 프롬프트에도 "문서에 없으면 모른다고 답하라"는 지시를 넣는다.
    - **문장형 답변:** 질문 맥락을 담은 완전한 문장으로 답하도록 프롬프트를 설계한다.
    - 구성 요소별 성능을 비교한다: BM25 / Dense / Hybrid / +Reranker
- **평가**
    - 검색: Recall@10, MRR@10
    - 생성: ROUGE-L, 정답 포함률(answer recall)
    - 답변 불가 판단: 도메인 밖 질문 1,000개에 대한 거절률, 의료 질문을 잘못 거절한 비율
- **산출물:** 의료 코퍼스, 인덱스, 성능 비교표

#### 2차 목표: 정량 검증과 성능 고도화 (MS MARCO v2.1 확장)

- **목표:** 1차에서 만든 답변 불가 판단과 문장형 답변을 공식 라벨로 검증하고 개선한다.
- **주요 작업**
    - v2.1의 의료 질문을 같은 방식으로 추린다.
    - **답변 불가 판단 검증:** v2.1에서 정답이 “No Answer Present.”인 질문(전체의 45%)을 라벨로 써서, 판단 정확도를 측정하고 임계값을 튜닝한다.
    - **문장형 답변 검증:** v2.1의 well-formed 답(전체의 12%)을 기준으로 생성 품질을 평가한다.
    - 프롬프트를 개선하고, 여유가 있으면 reranker를 fine-tuning한다.
- **평가:** 답변 불가 판단 정확도(Precision, Recall), well-formed 답 기준 ROUGE-L
- **산출물:** 1차 대비 개선 전후 비교표

#### 3차 목표: 의료 챗봇 서비스화

- **목표:** 실제 사용자가 쓸 수 있는 형태의 의료 챗봇을 데모한다.
- **주요 작업**
    - 채팅 UI를 만든다
    - 답변에 출처 passage와 URL을 표시한다.
    - 의료 안내 문구를 넣는다. 예: "의학적 조언이 아니며 전문의 상담을 권장합니다"
- **평가:** 응답 시간, 데모 시나리오 점검
- **산출물:** 데모 서비스, 최종 발표 자료
