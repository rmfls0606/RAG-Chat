# 의료 QA 테스트셋 Holdout 방법

기존 train 데이터에서 질문 350개를 평가용으로 분리했다. 모델 학습에는 분리 후 남은 6,047개를 사용하고, 보류한 350개는 최종 평가에 사용한다. 질문과 정답, 문맥은 원본 행의 값을 유지한다.

## 분할 개요

| 구분 | 행 수 | 사용 목적 |
|---|---:|---|
| 원본 train | 6,397 | 분리 전 학습 데이터 |
| 학습용 잔여 train | 6,047 | 모델 학습 및 튜닝 |
| holdout test | 350 | 학습에 사용하지 않는 평가 데이터 |
| 기존 validation | 1,162 | 원본 validation 용도 유지 |

분할 관계는 `원본 train 6,397 = 학습용 6,047 + holdout test 350`이다.

## 데이터 구성과 검증

테스트 행은 원본 질문, `answers`, `context` 및 나머지 메타데이터를 유지한다. 유형과 분류 근거를 확인할 수 있도록 `question_category`, `matched_keyword` 열을 추가했다. 테스트 파일의 `split` 값은 `test`이다.

- 테스트 350개에서 `query_id`와 `query`가 각각 고유하다.
- 테스트 ID는 잔여 학습 데이터의 ID와 겹치지 않는다.
- 테스트 행의 결측치는 없다. 기존 validation 1,162개는 그대로 보존했다.
- 고정 시드 `20261102`로 같은 원본 데이터에서 동일한 표본을 재생성할 수 있다.

## 사용 절차

| 단계 | 파일 | 사용 방법 |
|---|---|---|
| 학습 | `data/derived/medical_train_without_test.parquet` | 이 파일의 train 6,047개를 모델 학습에 사용한다. |
| 평가 | `data/derived/medical_test_350.parquet` | 학습과 튜닝에 사용하지 않은 상태로 최종 성능을 평가한다. |

평가 결과를 확인한 뒤 모델이나 프롬프트를 반복 조정하면 holdout 정보가 튜닝에 반영된다. 이 경우 해당 데이터는 독립적인 최종 평가셋으로 간주하기 어렵고, 별도의 보류 평가 데이터가 필요하다.

## 파일과 재생성

- 테스트셋: `data/derived/medical_test_350.parquet`
- 학습용 잔여 데이터: `data/derived/medical_train_without_test.parquet`
- 유형별 분포: `data/derived/medical_test_350_distribution.csv`
- 검증 기록: `data/derived/medical_test_350_manifest.json`
- 생성 스크립트: `scripts/create_medical_test.py`

프로젝트 루트에서 다음 명령으로 재생성한다.

```bash
python scripts/create_medical_test.py
```
