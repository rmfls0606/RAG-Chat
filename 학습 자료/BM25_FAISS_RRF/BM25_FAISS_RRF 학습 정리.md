# 용어 정리
### BM25(Best Matching 25) - 키워드 기반 검색
정의 : 단어가 얼마나 일치하는지로 문서의 관련돌르 점수화하는 전통적인 랭킹 알고리즘

특징 : TF-IDF를 개선한 방식이고, 
Elasticsearch나 Lucene같은 검색엔진의 기본 랭킹 함수로 쓰임.

점수 측정 방식
- 단어 빈도(TF) : 검색어가 문서에 많이 나올수록 점수가 올라감. 다만 일정 수준 이상은 점수가 크게 늘지도 않도록 포화(saturation) 시킴.
- 역문서 빈도(IDF) : "the", "은/는"처럼 흔한 단어보다 드문 단어가 일치할 때 더 높은 점수를 줌.
- 문서 길이 보정: 긴 문서가 단어를 많이 포함한다는 이유만으로 유리해지지 않게 조정.

장점 : 빠르고 학습이 필요 없으며 고유명사·제품 코드·전문용어처럼 정확한 단어 일치가 중요할 때 강함.

단점 : "자동차"와 "차량"처럼 뜻은 같지만 단어가 다르면 못 찾음.

### FAISS(Facebook AI Similarity Search) - 백터 유사도 검색 라이브러리
FAISS는 Meta가 만든 오픈소스 라이브러리로 고차원 벡터 중에서 가장 비슷한 것을 빠르게 찾는데 특화돼 있음.

흐름
1. 문서를 임베딩 모델에 넣어 숫자 벡터로 변환
2. 이 벡터들을 FAISS 인덱스에 저장
3. 검색어도 백터로 바꾼 뒤 거리(내적, L2 거리 등)가 가장 가까운 문서 벡터를 찾음.

특징
수백만 ~ 수십억 개의 벡터를 다룰 수 있도록 IVF(군집 기반), HNSW(그래프 기반), PQ(압축) 같은 근사 최근접 이웃(ANN) 기법과 GPU 가속을 지원. 의미 기반 검색이라 단어가 달라도 뜻이 비슷하면 찾아낼 수 있지만 정확한 키워드 일치에는 오히려 약할 수 있음.
| | BM25 | FAISS |
|---|---|---|
| 정체 | 랭킹 알고리즘 | 벡터 검색 라이브러리 |
| 검색 기준 | 단어 일치 (희소 검색) | 의미 유사도 (밀집 검색) |
| 사전 준비 | 역색인만 만들면 됨 | 임베딩 모델 필요 |
| 강점 | 고유명사, 코드, 정확한 용어 | 동의어, 문맥, 바꿔 말한 표현 |

### 함께 쓰는 경우 : 하이브리드 검색
RAG(검색 증강 생성) 시스템에서는 둘의 장점을 합치려고 BM25 + FAISS를 같이 쓰는 하이브리드 검색을 많이 사용. 두 검색 결과를 각각 뽑은 뒤 RRF(Reciprocal Rank Fusion) 같은 방법으로 순위를 합치면 키워드 정확성과 의미 이해를 모두 챙길 수 있음. LangChain의 `EnsembleRetriever`가 이런 구성의 대표적인 예.

### RRF(Reciprocal Rank Fusion)
정의 : 여러 검색 시스템의 결과를 점수가 아니라 순위만 보고 하나로 합치는 방법

필요성
BM25 점수는 12.7, 8.3처럼 범위가 정해져 있지 않고 FAISS 유사도는 0.82, 0.79처럼 0~1 근처 값이다 보니 단위 달라서 그냥 더하면 한쪽 점수가 결과를 좌우해 버림. RRF는 점수를 버리고 "몇 등이었는지"만 써서 이 문제를 피함.

계산 방식 : 

`RRF 점수 = Σ 1 / (k + 순위)`

- 순위는 각 검색 결과에서 그 문서가 몇 등인지(1등, 2등, ...)

- k는 보통 60을 사용. 상위 1~2등이 지나치게 큰 점수를 가져가지 않도록 완충하는 상수

- 한쪽 결과에만 나온 문서는 그쪽 점수만 더함

| 문서 | BM25 순위 | FAISS 순위 | RRF 점수 (k=60) |
|---|---|---|---|
| A | 1 | 3 | 1/61 + 1/63 ≈ 0.0323 |
| B | 2 | 1 | 1/62 + 1/61 ≈ 0.0325 |
| C | 3 | — | 1/63 ≈ 0.0159 |
| D | — | 2 | 1/62 ≈ 0.0161 |

장단점

장점은 구현이 몇 줄이면 끝날 만큼 단순하고 점수 정규화나 가중치 튜닝 없이도 꽤 잘 작동함.

단점은 점수 차이 정보를 버림. 예를 들어 1등이 2등보다 압도적으로 관련 있더라고 RRF에서는 그냥 한 등수 차이로만 취급. 그래서 더 정교하게 하고 싶으면 점수를 정규화해서 가중 합산하거나, 합친 결과를 리랭커(reranker)모델로 한 번 더 정렬.
